# ADR-009: Verified Portfolio Showcase Architecture

## Status
**ACCEPTED** (2026-09)

## Context
Traditional developer portfolios consist of unverified self-hosted websites, links to toy projects, or static PDFs. Hiring managers cannot determine whether the code was written by the candidate, copied from a tutorial, or generated by an LLM without understanding. We require a portfolio system that transforms coursework, gate completions, and capstones into an **externally verifiable, interactive technical showcase**.

## Decision
We implement a **Verified Portfolio System** under `domains/portfolio/` and `features/portfolio/`:
1. **Public Showcase Page**: Dynamic route `app/portfolio/[username]/page.tsx` rendering candidate profile, verified gate certifications, mastered competencies, and capstone case studies.
2. **Cryptographic Verification**: Every listed gate certification links to a public verification URL checking the immutable `gate_completion` record.
3. **Interactive Project Previews**: Sandboxed iframe embeds and direct GitHub commit audit trails showcasing real-time deployed software.
4. **Social & Professional Sharing**: Generates dynamic OpenGraph preview cards (with competency scorecards and gate badges) for LinkedIn and Twitter.

## Alternatives Considered
- **Static Export / Resume PDF Generator**: Fails to provide interactive verification, live code execution, or dynamic badge checking.
- **Third-Party Credential Platforms (Credly/Badgr)**: Disconnects the credential from the candidate's actual source code, test suites, and architecture documentation.

## Tradeoffs
- **Public Traffic Handling**: Public portfolio pages experience external traffic spikes when shared on social media or job applications.
- **Privacy Granularity**: Requires fine-grained visibility controls so learners can choose which artifacts are public, recruiter-only, or private.

## Risks
- **Security Vulnerabilities in Embedded Projects**: Malicious scripts running inside portfolio preview embeds.
- **Mitigation**: Sandboxed `<iframe>` tags with `sandbox="allow-scripts allow-same-origin"` and strict Content-Security-Policy (CSP) headers.

## Consequences
- Candidates possess a modern, tamper-proof portfolio that stands out in technical recruiting pipelines.
- Employers gain instant confidence in candidate competence through auditable proof artifacts.
